## 本轮交付与边界

本轮只新增这份审查清单，不修改程序、算法、工作簿或桌面快捷方式，不运行测试程序、GUI自动化、宏或Excel重算。后续实现以用户人工验收为交付检查点，验收前不推送或创建PR。

## 状态定义

- **已有**：源码存在输入传递和计算路径；不等于数值已全面验证。
- **显示缺口**：内部已计算或结果快照已保存，但计算单弹窗缺少细节。
- **模型缺口**：没有独立选型/来源字段，无法完整保存和重现该选择。
- **分支未开放**：选项或部分公式存在，但入口仍拦截；不是可计算功能。
- **依据待核对**：公式分支可定位，但完整链、数据或参考算例不足，不能解锁。

### S：国标／非标

原表入口：线圈型式T2/T3与U2，计算单F3。原表非标指标AN2/AN3/AN4/AN5为独立手填值。

明确的关键分支：`计算单!O9 = IF(F3="非标",AN3,LOOKUP(H1,外部Sheet1!A41:A60,F41:F60))-0.34`。本轮没有把0.34定义为通用国标公差，也不准备直接移植为程序默认约束。

- `TransformerParams.h`只有损耗手工来源标记及各标准值，没有F3对应的标准模式。
- `ParamTableWidget::applyModelLinkage`自动覆盖空载/负载/总损耗，阻抗和空载电流保留手工值。这是现有行为，不等于完整国标/非标选择。
- `DesignDatabase::noLoadCurrentStd`已有数据接口，源码搜索未发现界面/引擎调用；O9来源链没有接入该接口。接口采用阶梯查表，新增国标模式前还需核对容量匹配、边界和来源。
- `SchemeConstraints.h`负责把实际值与指标及允许偏差比较；标准值≤0时跳过对应项。必须明确“跳过”不是“合格”。
- `GridOptimizer.cpp`按`checkSchemeConstraints`筛选；弹窗成功重算/确认没有在这条路径调用该约束函数。**计算有效≠符合性能指标**；第一批应显示分开的计算状态和指标状态，不先改变是否允许保存的产品规则。
- `SchemeStore.h`保存的是CalcInput，未完整保存TransformerParams指标及来源。新增国标/非标前必须制定旧方案迁移和来源保存规则，不能只增加下拉框。

国标/非标首先影响指标来源和合格判断。除非原表有明确依赖，不能让切换标准自动改电磁实际结果，也不能自动修改全部偏差值。项目内置表状态不构成现行标准认证；如后续声称法定标准适用或最新版要求，另行核对正式来源。

## 后续分批设计与验收入口

推荐方案：保留既有可靠链，统一输入→实际采用值→中间结果→最终结果→指标校核的数据路径。与“只在UI追加回调”相比，这能避免表格显示已变但引擎或保存仍用旧值；与“一次重写所有算法”相比，每批能独立人工验收。此处是路线设计，不是未核实算法的实现指令。

### 第一批：已有链可观察、状态可区分（不扩算法）

拟涉及：`CalcResult.h`、`ElectromagneticEngine.cpp`、`EmResultPanel.cpp`、`SchemeCalculationSheet.{h,cpp}`、`EnterCalcPage.cpp`及本批验收说明。

1. 从本次引擎计算保存基础电量快照（高低压相电压、相电流等），只赋值已有计算量，不在前端重复推导。
2. 单独保留实际心柱查表磁密I25，并将F16明确为设计磁密；展示已有实际截面、心柱/轭重量及几何叠积快照。
3. 若展示逐级片数/实际叠厚，必须由`calcCoreWeights`保存本次中间量；不能用几何叠厚冒充取整后叠厚。逐级表设计须保持弹窗编辑焦点和稳定行列。
4. 自动重算后按当前`pendingParams/pendingResult`显示指标校核摘要，分开“计算成功”“指标超限”“指标未校核”“旧结果未更新”。沿用`checkSchemeConstraints`，不在此批擅自修改确认保存规则或约束公式。
5. 不改变手工实际匝数，不开放Dd/Yd、其他形状或分段，不把国标/非标假实现成标签切换。

人工验收位置：方案选择→选择→计算单弹窗，检查Dyn/Yyn的相电量及高压匝数、同厚/异厚硅钢的材料与实际截面、不同绝缘增厚的绕组尺寸。设计变量改变引起的最终结果按原链跟随，不要求每个取整值都变。提高/降低性能指标时，实际电磁结果应不被指标值直接篡改，但校核状态应按当前指标变化。取消不保存，确认收集最新值。

本批实现前需用户审阅此清单并确认展示范围；本轮未修改程序，故桌面当前版本没有新增这些字段。

### 第二批：国标/非标与指标来源

拟涉及：`TransformerParams.h`、`ModelStdTable.h`、`DesignDatabase`、`ParamTableWidget`、`SchemeStore`及入口/结果打印。先确定F3及AN2:AN5对应关系、O9减0.34口径、自动值/合同值/允许偏差边界，再定义可保存的模式。禁止用“无法匹配标准表”自动宣称“非标已确认”。

人工验收：内置适用规格自动值、非标手工指标、修改/切回模式、缺失来源、保存重开；标准切换与实际计算值/约束状态分别核对。

### 第三批：硅钢与心柱/轭现有链

先完善椭圆现有中间量对照；完整核对线圈型式的AA/AB阶梯列及Sheet1的工艺常量与计算依赖。确定同心柱/T形轭模型、旧方案默认含义和保存后才实施独立分支。没有双分支样本时维持原支持边界，不用默认数组宣称两种轭算法已认证。

人工验收：指定硅钢/几何组合的片数、截面、磁密、重量、铁损及下游尺寸；同心柱/T形轭须各有可核对样本。

### 第四批：导线、绝缘、油道与圆筒绕组

继续核查裸/绝缘尺寸、材料、并绕/叠绕、油道开停的组合链；不擅自增加不明绝缘材料映射。先验收已支持圆筒式，再把分段串联作为单独算法任务，不把油道分区当分段串联。

人工验收：圆/扁切换、预设/自定义恢复、并/叠根数、实际匝数与推荐区分、油道停用及非法布局、尺寸→阻抗→温升→成本链。

### 后续独立算法批：Dd/Yd、圆/长圆、分段

各任务先完成原表全分支依赖和适用数据审查，并给出独立人工对照样本；再分批实现和开放。不能先解除UI拦截、不能把未知钟点号或其它形状当默认分支。未获得足够依据时继续做已支持范围内的改进，不推测算法。

## 交叉组合与完成标准

- 每批不只验单个下拉：同时覆盖接法×标准、心柱×铁轭、材料×线形×绝缘、线圈形式×油道、硅钢×实际匝数。
- 未支持组合必须阻止实际计算；已支持组合应能追溯实际采用值，不能依赖旧结果或未采用的推荐值。
- 本次结果快照供显示与打印；保存/导入不得丢失会改变计算/判定的选择。旧方案迁移规则需明确，非法新值不可默默回退。
- 自动重算不重建正在编辑的表格，不丢焦点；输入无效和算法不适用时清晰标记旧结果，不宣称当前计算成功。
- 后续每批列程序改动位置、原表依据、预期变/不变项。按用户要求不新增或运行测试程序，由编译/静态审查和用户人工验收交付。
- 全矩阵列出的是工作范围，不是全部已实现或已经验证的承诺。
