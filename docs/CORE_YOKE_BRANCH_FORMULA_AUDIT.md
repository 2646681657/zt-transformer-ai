## 结论

## Sheet1与“线圈型式”不能混为一张表

已核对当前文件：

- Sheet1 B5:B20及部分D列通过“计算单”获取片宽/叠厚；D5=2×G18，后续级在汇总中按对称项处理。
- Sheet1 C6:C8为手填180；D17/D18为手填1.5/2，D19/D20为0。D16引用F20，并非D17/D18也自动引用G20/H20。
- Sheet1 E列既有公式`(C5-Ci)/2`，也有0、5、10、15、25、35等字面量。所检查Sheet1公式中未发现直接引用“线圈型式”的公式。
- 几何截面Sheet1 D23/J23读取各自B/C、D列；实际截面I24/O24读取取整后的实际厚度，I25/O25由实际截面求磁密。重量E22、铁损T26仍由这套Sheet1链得到。

因此目前不能仅把线圈型式E列选中的AA/AB阶梯覆盖Sheet1 E列，就宣称得到与原单等价的同心柱重量/铁损。需要明确原使用流程是否会人工更新Sheet1工艺值，并取得对应工艺依据或经过确认的方案样本。当前文件压缩包未见内嵌vbaProject.bin；这不证明原工作流程没有其他外部更新操作。

另一个待核对点：AC47外表面项仍直接乘P12/180，而P12在非椭圆时返回空字符串。未在Excel重算，不能仅凭文本确定其最终运行行为，更不能认为全部非椭圆散热路径已经验证。完整迁移前需单独核对该处，不用程序自行假设的角度分数掩盖来源差异。

## 现有程序的实际边界

- `StructureConfig.h`包含心柱枚举，但`CalcInput`及方案JSON没有完整的心柱/铁轭类型字段；`ElectromagneticEngine::calcCoreGeometry`直接使用椭圆角、大圆/小圆几何。
- `DesignDatabase::coreWidths/coreYokeBase`已有阶梯查表接口；当前引擎固定传椭圆短轴。接口存在不证明已核对圆形/长圆形所需数据范围和来源。
- 当前轭片宽放大、补充片叠厚、阶梯手工值有各自输入；不能把这些值等同于原单铁轭选项已经迁移。
- 方案弹窗F4心柱选项、F5铁轭选项对未支持类型仍禁算；F5当前为本地控件状态，不是持久化算法类型。
- `ConnectionBarChordReference`的K19/K20累计表明确按椭圆首行0构造；长圆形首行B20/D20不同，不能无调整复用。
- 其他形状完整计算、确认保存及寻优限制继续有效。Dd/Yd非标计算能力不因本轮对照而改变。
