# 第三批：独立测试、模型比较与人工审核设计

## 已确认目标

用户批准第三批：同一批样本比较原公式/不同DNN；保留未用于训练和选模型的独立测试产品；人工审核后启用；异常时回退。真实数据后补，不编造工程门槛，不把流程测试当成精度证明。

本设计是新增审核子系统，实施前请用户复核以下边界，尤其“启用”的含义和企业门槛来源。第一、二批及所有未提交修改保持原样。

## 1. 独立测试和模型比较

- 使用当前已保存样本另行导出冻结测试包，包含来源、产品分组、设计快照、原公式值、实测标签及文件摘要。不得自动生成企业数据。
- 固定模型后才执行测试；测试不更新权重、归一化或最佳轮次，不将测试结果回灌训练。
- 对每个模型/目标，测试产品组必须与该模型全部训练组和验证组不重叠。旧模型无完整分组记录则不能取得审核证据，须重训；仅改样本ID、日期不能绕过同产品拦截。
- 对比必须使用同一个冻结测试集；缺标签按目标说明，缺目标、不适用、越界和预测失败逐项计数。不得悄悄丢弃难预测的样本后声称模型更优。
- 显示原公式/DNN的MAE、RMSE、最大绝对误差、样本数、独立产品数、覆盖率和失败原因；差值方向写清楚。基线误差为0时不算除零改善率。
- 测试集曾用于比较/挑选模型后，不再宣称对后续版本仍是完全盲测。保留使用记录，提示需要新增最终验收产品；本地记录不能证明企业外部从未使用该数据。
- 测试/合成标识传播至全部结果，任何测试模型/测试证据不能用于启用。

## 2. 门槛与审核

- 企业审核策略按目标配置：指标单位、最大MAE/RMSE/最大绝对误差、最少独立测试产品数，以及是否要求不劣于原公式。没有默认合格值，不自动用现有10%对比提示或5产品运行门槛替代。
- 门槛必须为有效有限值且必填字段完整；只有企业确认后才能冻结为有版本和来源的审核策略。策略变动使旧审核失效，需要按新策略复核。
- 启用前必须有：非测试模型、完整模型/验证报告、成功且无产品组泄漏的独立测试、所选目标100%预测覆盖、符合已确认策略、审核人和理由。任何一项缺失均明确拦截。
- 审核人名称是本地操作记录，不声称具备身份认证、电子签名或企业权限控制。若企业要求可认证审批，应另接账号权限体系。
- 审核记录绑定模型/报告/测试集/测试结果/策略的SHA256以及适用范围，修改任何产物后审核不得沿用。记录按事件追加；记录写入失败不得更新启用状态。

## 3. 启用的建议含义（需要复核）

本批“启用”仅将已审核模型设为默认的**独立修正展示模型**。原公式值仍独立保留，修正列标注模型版本和审核状态。不修改CalcResult，不改变合格判定、材料价格、报价、打印原公式值或寻优筛选。

如希望本批直接用DNN替代正式计算/寻优，需要另行明确目标和工程验证规则，不能将两种“启用”混为一谈。

- 每次使用前重新核验产物摘要、审核、策略、结构/公式版本、固定物理上下文及特征范围；失败则不提供修正值，原公式值照常显示，禁止用0或旧预测填充。
- 停用：默认独立模型清空，不删除数据或历史。
- 回退：只允许回到仍满足当前完整性和审核规则的历史已审核版本；不能回退到测试、过期、损坏或被撤销版本。没有合格历史版本时不提供回退操作。
- 活跃模型切换、停用或回退时清空旧预测及其悬停版本说明；运行中的预测结果不得覆盖新的活跃状态。

## 4. 模块与持久化

- Python：新增独立测试/比较命令，复用安全JSON模型加载和范围检查；不改现有训练目标或原C++公式。
- C++：独立审核/状态存储模块，统一完整性校验、策略判定、审计事件和原子活跃状态切换，使用进程间锁，避免多个窗口丢失更新。
- 界面：训练与模型页新增“独立测试与比较”“审核标准”“审核/设为默认独立模型/停用/回退”；所有阻断原因可见，不做仅外观可点击的空按钮。
- 数据独立保存在self_learning的review/test_runs及registry目录；不覆盖samples.json或既有模型；不上传。

## 5. 验收与限制

先测试失败情形再实现：产品泄漏、无标签、无已确认策略、测试模型、部分覆盖、原公式零误差、产物/策略篡改、并发写入、无合格回退版本、过期异步预测、持久化失败。真实训练/预测链路仍需回归，不能只用模拟成功报告验证。

合成数据只测试流程和拦截，不获得启用资格。没有真实数据与企业门槛时，允许验证比较界面和审核拦截，不声称已经完成生产上线验收。

编译、回归、独立审查通过后，按原习惯备份并替换桌面快捷方式对应程序；运行中须先由用户保存并关闭。待用户验收后再提交源码。
