# 计算分支对照第一批：联结组别

日期：2026-10-15。界面第四批已人工验收。本轮只读核对原工作簿和现有源码，不改计算公式、不放开Dd/Yd、不替换桌面程序、不运行测试程序或Excel重算。

## 结论

原计算单的Yyn、Yd、Dyn、Dd通过两侧接法驱动同一套相电量公式，再向后传递。当前引擎已有两侧接法布尔量及基础公式，不能笼统称Dd/Yd“完全没有算法”；但当前输入收集、校验、预览及内置标准匹配只完整接入Dyn11/Yyn0，不能仅删除禁算判断就认为完成支持。

这是公式文本和代码路径对照，不是四种接法全链数值认证。未运行宏、未验证外链重算，也未认证接线相位、引线结构、试验和制造要求。原单只给出Yyn/Yd/Dyn/Dd标签，不能凭此推导所有钟点数均适用。

源文件：`D:/zt-transformer/zt-transformer-ai-main/SB20-M-630-10计算单.xlsm`。

- `线圈型式!Q10:Q13`依次为Yyn、Yd、Dyn、Dd。

## 基础公式与已有引擎

源码位置：`qt-app/src/engine/ElectromagneticEngine.cpp`的`calcElectrical`，输入来自`CalcInput.h`的`hvDeltaConnected/lvStarConnected`。

| 原单位置 | 原单分支和舍入 | 现有引擎静态对应 |
|---|---|---|
| V6/Y6/AA6，第6行 | 高压Y接线电压除√3，否则用线电压，再ROUND到整数V | hvPhase；已具备两条分支 |
| AH6，第6行 | 低压d接用线电压，否则除√3并ROUND到整数V | lvPhase_V；已具备两条分支 |
| W7，第7行 | 容量/√3/高压额定kV，ROUND到2位A | hvLineCurrent_A |
| Z7，第7行 | 高压Y接用已取整线电流，否则再除√3，ROUND到2位A | hvPhaseCurrent_A；Y接直接使用已取2位的线电流，结果口径对应 |
| AG7，第7行 | d接容量/3/低压线电压×1000，否则容量/√3/低压线电压×1000，ROUND到2位A | lvPhaseCurrent_A；已具备两条分支 |
| AC4，第4行 | AH6/AH8，ROUND到4位V/匝 | turnVoltage_V |
| V8/Y8/AA8，第8行 | 各分接相电压/AC4，ROUND到整数匝 | calcWindingLayout的hvTurnsMax/Rated/Min |

程序不会因为切换接法而必然改变所有参数。特别是实际低压匝数AH8属于手工设计值，不能为了制造“联动很多”的效果自动覆盖。相电压改变后，固定实际匝数时匝电压、磁密和高压匝数可能随之改变；低压电流变化会影响电密和损耗。若工程师采用匝数建议重新设计，则是第二次明确的输入变更。

## 当前尚未接通的程序层

1. `ParamTableWidget.cpp`局部`SupportedConnection`仅有Invalid、Dyn11、Yyn0。Dd/Yd被解析为Invalid。
2. `saveToInput`仅对上述受支持接法写回高压D接，并把低压星接固定为true。解除提示而不改这里会保留旧值或错误沿用星接。
3. 主设计输入的相电量预览先检查受支持接法，因此Dd/Yd当前显示不可用。引擎`previewElectrical`本身已复用同一个calcElectrical。
4. `SchemeStore.h`已读写两个布尔量，不缺这两个JSON字段；但主页面回填及参数表显示会把低压d接标为暂不支持，仍需一致更新。接法标签与钟点数也需保持明确边界。
5. `ModelStdTable.h`仅有loadDyn_W和loadYyn0_W两列。当前standardUnavailableReason先挡住不支持接法；若扩大解析范围但不拆开“电气可计算”和“内置标准有依据”，非Yyn接法可能误入Dyn列。
6. 主设计、方案弹窗、导入回填、确认保存和寻优入口须一起检查，避免一个入口可选、另一个入口静默回退。保持其他适用范围限制不变。

## 标准来源与原单的证据限制

- 本工作簿L9/M9是保存的手工数值，不是自动随四种接法切换的查表公式。不能用该样本宣称四种接法共用相同标准。
- O9仍引用外链表，并含减0.34的修正。外链工作簿未在本轮打开重算，该修正不能无依据推广为通用规则。
- 项目内置表没有Dd/Yd专用列。现有源码的表注释不是本轮对现行标准适用性的外部核验。
- 可以研究在“非标、人工确认性能指标”模式下接入Dd/Yd，但仍须完成电气和下游路径审查及人工对照，不能把非标模式当作算法验证替代品。
